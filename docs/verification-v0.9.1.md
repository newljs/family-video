# v0.9.1 启动体验与后台连接

日期：2026-10-26。客户端版本：家长 `0.9.1+11`、儿童 `0.9.1+14`；Go 服务端和数据库版本保持 v0.9.0 / schema v6。

## 启动行为

- 首次配置服务器仍需验证地址和服务兼容性。已有地址时，先恢复本地目录和上次页签，儿童端同时恢复上次视频 ID 与既有播放进度；目录缓存按服务器、客户端角色和数据类型分别保存。
- 儿童端先恢复本地每日额度，再展示目录；额度已用完时只展示指定合集，旧的“上次视频”不会绕过安静模式。离线文件检查异步分批执行，不挡住目录恢复。
- 视频、合集和家长任务等请求并行开始。后台同步逐项更新页面，先返回的视频可以先播放；合集或任务较慢时不会锁住收集箱、导航和已显示的内容。手动刷新仍采用成功后完整替换的方式，失败保留当前内容。
- 后台连接只显示轻量状态。目录请求整体截止时间为 5 秒（含读取响应体），健康检查为 3 秒；超时触发 HTTP 请求中止，防止后台无限堆积连接。上传继续使用单独的长超时。
- 同一客户端复用 HTTP 连接；兼容性检查在当前进程、当前服务器内复用 5 分钟，保存新地址时仍验证新服务器。旧 token 仅作本地缓存命名，迁移后的命名信息写入偏好设置，避免每次启动重复读取安全存储。
- 同步合并重复请求，失败后在前台按 5、15、30、60 秒间隔重试；退后台取消重试计时，回到前台立即同步。更换服务器与主动刷新会淘汰旧同步结果，页面销毁后不再更新 UI。
- 缓存目录中的网络视频在获取新目录前只展示封面与标题，避免启动时用过期签名初始化播放器；完整离线下载仍可直接播放。部分原生播放缓存不保证完整离线可播。
- 后台刷新保留当前播放器。相同不可变媒体的签名轮换不会使播放器重新初始化；真正改变来源或播放器已失败时会重新加载。刷新失败不重置当前播放页。

## 使用边界

升级后需成功同步一次，才有新版本的目录快照可供下次启动使用。旧版的完整离线下载、喜欢和进度沿用原来的设备数据。首次安装且没有任何本地内容时，仍需联网获取目录；“先显示缓存”不能让未下载的视频在服务器离线时完整播放。

后台同步发生在应用进程存活且处于前台时，没有新增 Android 常驻后台服务。真实冷启动首屏耗时、Wi-Fi 质量、系统启动和原生首帧解码仍需真机测量，本轮不宣称已经达到固定的 1 秒启动指标。

## 验证

- `scripts/check.ps1`：Go tests/vet、两端与共享包/播放器适配包的 Flutter 分析及 Dart 测试通过。家长端保留 4 项原有弃用 info；本轮新增代码的风格提示已清理。
- 家长端 11 项、儿童端 39 项、共享 API 12 项、播放器适配包 58 项 Flutter/Dart 测试通过，共 120 项。全量脚本执行后，额外新增的无快照离线场景及播放列表重排、签名轮换场景分别通过专项回归。
- 新增测试覆盖：服务器请求挂起时缓存首页和导航可用、无缓存时离线仍可进入带导航的空首页、请求超时后缓存保留、安静模式先于缓存内容展示、视频先返回即可播放、后到的合集/列表重排/轮换的签名不重建播放器、缓存按地址/角色隔离、损坏快照忽略、健康检查复用、响应体卡住时中止请求、旧同步结果淘汰及前后台重试管理。
- 现有搜索测试改为在搜索面板内定位结果；刷新失败后首页仍保留同名视频，不再通过切换离线内容来改变首页播放器。

双端最终 debug APK 经 `scripts/build-android.ps1` 串行构建成功，产物为 `apps/parent_app/build/app/outputs/flutter-apk/app-debug.apk` 与 `apps/kids_app/build/app/outputs/flutter-apk/app-debug.apk`；使用 Android SDK aapt 核对包内版本为家长 `0.9.1+11`、儿童 `0.9.1+14`。核对 kernel 生成时间晚于最终源文件修改时间，产物包含本轮启动逻辑。

没有重启当前家庭服务或切换其已发布 APK 清单。正式签名覆盖安装和真实设备性能本轮仍未验收。
