# 小小放映室 TV

独立原生 Android 电视客户端，Kotlin + Android View + Media3 1.5.1，最低 Android 5.0 / API 21，包名 `cn.familyvideo.tv_app`。不依赖 Flutter，沿用现有 Go 服务端和家长管理端。Media3 固定旧版本以兼容 API 21，不可直接升级到要求 API 23 的版本。

## 使用

打开自动搜索约 4 秒：一台经过健康检查的家庭电脑自动连接，多台时选择；可用遥控器手动输入 `电脑IP:8765`。电脑防火墙允许 UDP 8766 与 HTTP TCP 8765。退出应用后不保存地址，下次重新搜索；切到后台而进程仍在时，地址只留在内存。

连接成功直接全屏播放，播完自动下一条，最后一条后循环。使用 MP4 Range，竖屏视频居中留黑边，不裁剪。不预加载下一条，不保留多个播放器。

| 遥控器 | 操作 |
| --- | --- |
| 上 / 下 | 上一条 / 下一条（连续快速按键合并后切换） |
| 确认 | 暂停 / 继续；连接失败、空列表时重试 |
| 左 / 菜单 | 文字合集列表、刷新、连接设置 |
| 右 | 显示标题、进度与按键提示，4 秒后隐藏 |
| 返回 | 先收起信息，再次返回退出；合集弹窗先关闭 |
| 系统播放 / 暂停、上一首 / 下一首 | 对应播放控制 |

单个资源加载失败时先检查服务，再刷新签名并重试一次，仍失败则跳过；全部失败后等待 30 秒再试。服务器不可达时保持重连状态，3–30 秒退避，不连续跳空整个目录。目录刷新失败后不拿旧目录继续换片；取得新的额度与目录后才允许选片。约 30 秒后台更新目录；更新不重建正在播放的媒体。退后台、按 Home、息屏触发 Activity 停止时释放播放器和解码器，回前台重新连接并从本条开头播放。

## 存储与观看规则

- 不使用磁盘媒体缓存、离线下载、封面缓存、数据库、SharedPreferences 或目录快照。不申请存储、相机权限；禁止应用备份和数据迁移。
- 地址、目录、合集、失败记录与观看事件只在内存。播放缓冲时间目标为 3–8 秒，起播 500ms、重缓冲 1 秒，字节目标 4MiB，回看缓冲为 0；这是加载策略，不是整个进程的内存上限。解码器、画面和系统仍需要内存。
- HTTP 使用 `no-store`；不安装 HTTP 磁盘缓存。Android 自身可能产生安装、编译和运行数据，系统应用数据统计不保证为 0。
- 使用系统 `ANDROID_ID` 作为 `X-Family-Client-Id`，服务端据此分开保存该电视的已看视频、观看时长与每日额度；该标识只读取系统值，不写入本地存储。每次进程启动后的首次目录会随机“全部视频”顺序，后续刷新保留当前会话顺序并追加新内容；已看完视频不进入全部视频队列，库内全部看完后由服务端清空该客户端的已看标记。
- 读取现有 `/api/settings/time-limit`，按实际播放推进时间采样，暂停、缓冲、跳转不计时；约每 10 秒上报 `/api/watch`，稳定事件 ID 用于服务端去重。退出时尽力补报，内存重试队列最多 512 条；进程终止、断电或极长网络故障可能丢失未上报事件。电视本地不保存观看历史，服务端仍保存统计。
- 本地未上报时长参与额度判断。额度用完允许当前视频自然结束，下一条仅从家长指定的安静合集中选；未指定或合集为空则停止选片。每 30 秒同步规则，也可通过菜单刷新。连接未取得规则时不开始播放；跨天以新的服务端规则为准。
- 依赖 v0.9.2 已有的发现、目录、合集、时长、MP4 媒体接口；旧服务无自动发现时可手输地址。无需为了播放先升级客户端安装包发布接口。

## 构建

需要 JDK 17+、Android SDK Platform 35、SDK build-tools。脚本优先使用 Flutter 已配置的 JDK；可显式传 `-JavaHome`。通过 `ANDROID_HOME` / `ANDROID_SDK_ROOT` 或本地未提交的 `local.properties` 指定 SDK。

```powershell
# 默认体验包：R8 + 资源压缩，以本机 Android debug key 签名
.\scripts\build-tv.ps1
# 正式包：使用与其他客户端相同的 FAMILY_ANDROID_* 签名环境变量
.\scripts\build-tv.ps1 -Mode release
# 发布至家庭服务器的数据目录，供管理台下载（需包含 TV 注册的新服务）
.\scripts\build-tv.ps1 -Mode release -Publish
```

体验包输出 `bin/family-video-tv-trial.apk`，Gradle 原始文件为 `apps/tv_app/app/build/outputs/apk/trial/app-trial.apk`。正式包使用 `release` 替换 `trial`。体验包和正式包包名相同，但签名可能不同，首次改装正式签名时需要先卸载体验包。签名材料与 APK 不提交 Git。

后续发布新包前在 `app/build.gradle.kts` 递增 `versionCode`；服务端会拒绝以相同或更低构建号发布不同内容的 APK。APK 内 `assets/THIRD_PARTY_NOTICES.txt` 与 `assets/LICENSE-2.0.txt` 保留运行依赖的第三方说明与许可证。

安装到电视可用 U 盘，或在启用电视网络调试后使用 `adb connect 电视IP:5555`、`adb install -r bin/family-video-tv-trial.apk`；不同电视是否允许安装与调试需要真机确认。应用同时提供传统桌面入口和 TV Launcher 入口。

脚本同时执行 TV JVM 单元测试和 Android lint；仓库完整检查为 `scripts/check.ps1`，加 `-NativeAndroid` 时也构建 TV、家长与儿童端。

## 当前边界

当前直接播放服务端已有 MP4，**没有新增 720p 转码产物**。电视上把显示区域改成 720p 无法降低高分辨率源的解码成本。先用 H.264/AAC、720p、25/30fps 内容验证；若老电视播放现有高分辨率内容吃力，再由 Go worker 后台生成 TV 专用资源，完成前不暴露，禁止在播放请求中转码。

不含下载、喜欢、搜索、封面墙、手动快进、应用内升级和开机自启。Android 5.0 为构建兼容下限，实际老小米电视的系统版本、遥控器、声音、解码能力及待机唤醒需真机验收。测试记录见 [TV 验证说明](../../docs/verification-tv-v0.1.md)。
